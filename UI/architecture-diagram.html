下一階段 UI 架構圖

FastAPI（localhost）+ React + pywebview　·　Phase 0：尚無 backend/ frontend/　·　搭配 docs/UI/ 交接文檔閱讀

一句話：前端（TypeScript）↔ HTTP ↔ 後端（Python）三層物理分離；HTTP 是防火牆，演算法永遠不知道 web 存在。

1. 分層架構

由上而下：醫師雙擊 → pywebview 視窗內嵌前端 → 跨 HTTP → FastAPI 後端（api / algorithms / io）→ 本機檔案。

🟪 doctor-pc　雙擊 .exe
PyInstaller 打包；不要求裝 Python / node。影像全程留在這台機器。
▼
pywebview native window ▸ frontend/（React + OpenSeadragon）
Chromium 內嵌視圖。純 TypeScript，看不到 Python、不讀本機路徑。
▼
◄─ HTTP 物理防火牆　127.0.0.1:PORT　（只綁 localhost，不對外）─►
▼
backend/　FastAPI（只綁 127.0.0.1）
Python 後端。
api/
HTTP endpoints＝唯一介面。只驗證＋呼叫＋回檔案路徑，不放演算法。
algorithms/
你的演算法（純函式，不動）。禁止 import fastapi。可被 CLI 獨立呼叫。
io/
WSI 讀取、金字塔切片（openslide / pyvips，不手刻）。
▼
🟧 local filesystem
影像 + 結果檔，不進 git。大影像永遠留這，HTTP 上只跑輕量 JSON 與逐塊 JPEG。

前端（TS） api 轉譯層 algorithms 純函式 filesystem 　—　紅色斜紋條＝HTTP 防火牆，兩層唯一的接觸面。

3. 座標轉換邊界

兩套座標系，換算只在一個檔發生。演算法永遠不碰 viewport，前端永遠不碰 pixel。

🖥 瀏覽器端
DeepZoom viewport 座標（正規化 / tile 相對）。OpenSeadragon + Annotorious 畫 ROI。
→ HTTP →
★ backend/api/roi.py
唯一換算點：viewport ⇄ pixel。牽涉金字塔 level / 縮放 / 原點對齊——集中在這裡，出錯只查一個檔、只寫一組測試。
→
⚙ 演算法端
原始影像 full-res pixel 座標。algorithms/ 只認這個。

4. 護欄紅線（7 條）

維持「UI 與演算法結構性分離」的物理界線。踩線＝架構退化成一坨黏合的 code。✕＝禁止。

✕algorithms / io import web 框架
不得 import fastapi / flask。演算法要能被 CLI 獨立呼叫。
✕frontend 直接讀本機路徑
只透過 /api/tiles 等 endpoint。前端拿 slide_id 不拿檔案路徑。
✕api 層放演算法邏輯
只驗證＋呼叫＋回路徑。endpoint 內不得有 numpy 運算 / 影像處理。
✕座標換算在 roi.py 以外
viewport⇄pixel 只在 api/roi.py。
✕一次 PR 跨多層
改前端別同時改演算法。單層 PR 才能逐條 review。
✕Phase 1 搬檔順手重構
只改 import path，函式內容不動。驗收：輸出 bit-identical。
✕numpy array 跨 API 傳
邊界一律「檔案路徑 + JSON metadata」。大影像留 filesystem。
