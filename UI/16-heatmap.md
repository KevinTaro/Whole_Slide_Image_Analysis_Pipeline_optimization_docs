## 1. 一句話

熱圖是**事後從 `report.csv` 算出來的**：把每顆細胞依質心分進固定的 1024 px 格子，每格算兩個
數字（擴增比值、異質性分型），前端把它們畫成兩個可各自調透明度的圖層，疊在切片上。

不存檔、不參與分析流程。每次開啟報告時現算，所以換色階、換門檻、修 bug 都不必重跑分析，
已經在硬碟上的舊報告也自動有熱圖。

```
report.csv ──m5_heatmap.build()──▶ 每格統計 ──GET /api/hybrid/heatmap──▶ HeatmapGrid(JSON)
                                                                              │
                                              ┌───────────────────────────────┤
                                              ▼                               ▼
                                   擴增：canvas 一格一像素填色      異質性：SVG 一格一個外框
                                              └──────── OpenSeadragon overlay ────────┘
```

## 2. 後端：每格怎麼算（`m5_heatmap.py`）

### 2.1 格子

| 項目 | 做法 | 為什麼 |
|---|---|---|
| 格子大小 | 固定 1024 px（`HEATMAP_TILE_PX`），**不讀** `config.default_tile_size` | 一個是「分析切多大」，一個是「熱圖多粗」，碰巧同值但不該互相牽動 |
| 分格方式 | 依細胞質心：`col = centroid_x // 1024`、`row = centroid_y // 1024` | 分析用的 tile 彼此重疊 256 px、核心裁切後大小不一，拿來當熱圖格子無法比較 |
| 格線原點 | **全片 (0, 0)**，不是 ROI 原點 | 同一張玻片上不同框選的熱圖，格線才對得上、可以疊著看 |
| 回傳範圍 | 只回**有細胞的格子**，外加它們的最小外接範圍（`origin_col/row`、`cols/rows`） | 6×3 格的 ROI 不必回一張從全片原點鋪過去、99.8% 是空的畫布 |

### 2.2 每格的兩個數字

判讀邏輯只有一份，在 `m4_module/csv.py`。熱圖只負責分格，再把每一格丟回那裡既有的兩個
summary 類別，所以熱圖和 `summary.txt` 不會互相矛盾。

| 數字 | 來源 | 定義 |
|---|---|---|
| `ratio`（擴增） | `DotStatsSummary.from_results` | 該格有效細胞的 Σ黑點 / Σ紅點。有效細胞 = 未排除 + 蛋白陽性 + 紅點 ≥ 2，跟 `summary.txt` 的「黑點/紅點 比值」同一個式子 |
| `verdict`（異質性） | `Her2IthSummary.type_verdict()` | Type 1–5 或 Indeterminate，直接從 `report.csv` 的 `cell_type` 欄位點數，不重新分類 |

### 2.3 資料不足

一格的細胞太少時，數字回 `null`，前端畫成灰色的「資料不足」，**不是畫成 0**。組織邊緣常常
只有兩三顆細胞，畫成 0 會讓整圈邊緣看起來像強陰性。

- 門檻：`MIN_VALID_CELLS = 1`，只有後端認得，前端只判斷 `null`。
- `ratio` 看的是有效細胞數（`valid`）。
- `verdict` 看的是分型三桶合計（`typed` = 典型陽性 + 非典型陽性 + 陰性）。蛋白陽性未擴增
  與被排除的細胞不進分母。

## 3. API：`GET /api/hybrid/heatmap`

| 參數 | 意義 |
|---|---|
| `item_id`（選填） | 排程項目的報告；不給就是單次執行的輸出目錄 |

| 狀態 | 情況 |
|---|---|
| 200 | 回 `HeatmapGrid` |
| 404 | 沒有 `report.csv` |

`HeatmapGrid` 帶兩套座標，兩套都需要：

| 欄位 | 座標系 | 用途 |
|---|---|---|
| `col`/`row`、`origin_col`/`origin_row`、`cols`/`rows`、`tile_size` | 全片格線索引 | 在整張切片上定位 |
| `region_x`/`region_y`/`region_w`/`region_h` | 全片像素 | 這次分析的範圍；來自排程項目的 `item.json`（送出時的 ROI） |

`region_*` 的三種情況：

| 報告種類 | `region_x/y` | `region_w/h` |
|---|---|---|
| 排程項目，有框選 ROI | ROI 左上角 | ROI 寬高 |
| 排程項目，整張切片 | 0, 0 | `null`（沒有東西需要裁掉） |
| 單次執行（沒有 `item.json`） | `null` | `null` |

## 4. 前端：怎麼畫

兩張熱圖各是一個 OpenSeadragon overlay，錨定在**影像座標**（跟 ROI 選取框同一個做法），
所以平移縮放時格子會黏在它統計的那塊組織上。圖層都是 `pointer-events: none`，不會搶走
檢視器的拖曳和滾輪。

### 4.1 擴增熱圖：canvas 填色（`paintGrid`）

- 一格 = canvas 上的**一個像素**。畫布只有 `cols × rows` 大，由 OSD 拉伸到格線矩形；縮放在
  GPU 上做，平移時沒有任何逐幀 JavaScript。
- `image-rendering: pixelated`：不這樣設，瀏覽器會把相鄰格子的顏色內插在一起，「擴增」和
  「未擴增」的邊界就會落在內插決定的位置。
- 用 `putImageData` 一次寫入，不逐格 `fillRect`：整張切片有上萬格。
- 單一紅色階，五段，越嚴重越深、也越不透明：

| 比值 | 顏色 | 該格不透明度 | 標籤 |
|---|---|---|---|
| < 2.0 | `#fd968f` | 0.30 | 未擴增 |
| 2.0 – 3.0 | `#fe4145` | 0.55 | 輕度 |
| 3.0 – 4.0 | `#cf0523` | 0.70 | 中度 |
| 4.0 – 6.0 | `#940215` | 0.85 | 重度 |
| ≥ 6.0 | `#5c0009` | 1.00 | 極重度 |
| 資料不足 | `#898781` | 0.40 | — |

### 4.2 異質性熱圖：SVG 外框（`outlineGrid`）

- 每格畫一圈該分型顏色的**外框**，內部透明。分型是「身分」不是「程度」，顏色只需要被看到，
  不需要蓋住；填色會遮住它正在分類的那些細胞。
- 用 SVG 而不是 canvas：線寬設 `vector-effect: non-scaling-stroke`，在螢幕上固定 2 px。
  若用拉伸的 canvas 畫框，放大看細胞時線會跟著變成一條粗帶。
- SVG 的使用者單位是一格（`viewBox = 0 0 cols rows`），`preserveAspectRatio="none"`，
  跟 canvas 一樣被 OSD 拉伸到格線矩形。
- **每種顏色一條 `<path>`**，不是每格一個元素：整張切片有上萬格。
- 外框往格內縮 4%（`OUTLINE_INSET`），讓相鄰兩格不同分型時兩個顏色都看得到。
- **不滿一格的殘邊**：分析範圍只蓋到某格的一部分時，外框沿「被蓋到的那一塊」畫成封閉的
  長方形。若照整格畫，圖層的裁切會把框切開，缺一邊的框看起來像範圍還往外延伸。
  沒有記錄分析範圍的報告（單次執行）不知道邊界，照整格畫。

| 分型 | 顏色 | 意義 |
|---|---|---|
| Type 1 | `#056504` | 僅典型陽性 |
| Type 2 | `#1ac085` | 僅非典型陽性 |
| Type 3 | `#a6710f` | 典型 + 陰性 |
| Type 4 | `#fe8355` | 典型 + 非典型 |
| Type 5 | `#a32b61` | 三者具備 |
| 資料不足 | `#898781`（不透明度 0.40） | — |

`Indeterminate` 不在圖例裡，該格不畫。

五個色相是在「不能用藍、紫（蘇木精染色）、不能用紅（另一張圖層）」的限制下挑的，並以色覺
異常下任兩色仍可分辨為條件搜尋出來，量測數字記在 `frontend/src/lib/heatmap.ts` 開頭的註解。

### 4.3 透明度與圖例

- 兩張圖各一條滑桿，寫的是圖層元素的 `opacity`，拖動時不重畫、不重新掛 overlay。
- 預設：擴增 65%、異質性 0%。兩張圖蓋的是同一批格子，同時半透明會混出圖例裡沒有的顏色，
  所以預設只開一張。
- 圖例隨圖層出現（透明度 > 5% 才顯示）。擴增的色塊是實心，異質性的色塊是外框，跟圖上畫法一致。

### 4.4 兩個檢視、兩個座標系

同一份 `HeatmapGrid` 給兩個檢視用，差別只有「這個檢視的影像像素 (0,0) 在全片的哪裡」：

| 檢視 | 元件 | frame | offset | 看到什麼 |
|---|---|---|---|---|
| 疊合檢視 | `OverlayViewer` | `slide` | (0, 0) | 整張切片，各報告是上面的一小塊 |
| 結果圖 | `SlideViewer` | `region` | (`region_x`, `region_y`) | 分析範圍本身，熱圖鋪滿畫面並對齊每顆細胞 |

- 格線矩形：`x = origin_col × tile_size − offset.x`（`gridRectPx`）。
- 結果圖沒有 `region_x`（單次執行）時無法對位，**不畫**並顯示原因，不猜一個位移。
- 結果圖是哪一份報告，直接從 slide id 推：`hybrid_overlay_<item_id>` → 該項目，
  `hybrid_overlay` → 單次執行。數字和圖片不可能來自不同的報告。

### 4.5 裁切

格線是全片的，分析範圍的邊不在格線上，所以外接矩形一定會比實際分析的範圍多出最多一格。
多出來的部分若畫出來，就是在沒有數過細胞的組織上著色。`gridClipInset` 算出要裁掉的比例，
以 `clip-path: inset(…%)` 套在圖層上（用比例，所以不受縮放影響），同時也裁到影像本身的邊界。

### 4.6 滑鼠讀數

圖層不接收滑鼠事件，讀數是從游標位置換算的：游標 → 影像座標 → 加上 offset 回到全片 →
除以 `tile_size` 得到格子（`tileAtImagePoint`），再查該格的數字。游標落在分析範圍外
（即使還在格線外接矩形內）不出讀數。

讀數內容：座標、細胞數（有效數）、黑/紅比值、異質性分型；資料不足時寫出差幾顆。

## 5. 多份報告同時顯示（疊合檢視）

### 5.1 行為

- 疊合檢視會畫出**這組影像上所有已完成的報告**，各自蓋在自己的分析範圍上，不需要逐份開啟。
- 每個區塊角落有固定螢幕大小的標籤「報告 N」；左側排程清單顯示同一組編號。
  編號 = 該項目在「有結果的項目」中的排入順序（`lib/reportNumber.ts`）。刪除項目後，後面的
  編號會往前遞補。
- 面板上每份報告一個勾選框，預設全勾；兩條透明度滑桿所有報告共用。
- 範圍重疊時，**較新的報告畫在上面**，讀數也回報較新的那份。讀數第一行標明是哪一份。
- 勾選狀態存在檢視器內，切到結果圖再回來會回到全勾（透明度滑桿原本就是如此）。

### 5.2 哪些報告屬於這張圖

`aligned_her2` / `aligned_dish` 是**全域的 slide id**，每次發布新的對齊結果就改指向另一組
影像。只看 slide id 的話，換了對齊結果後，舊報告的熱圖會被畫在不相干的組織上，而且沒有任何
錯誤訊息。所以：

1. 排入分析時，後端把當時發布的對齊 run 記進項目（`item.json` 與 `QueueItem` 的
   `alignment_run_id`，選填欄位）。
2. 疊合檢視只畫符合下列條件的報告：

| 報告 | 是否顯示 |
|---|---|
| 在 `aligned_her2` + `aligned_dish` 上分析，且 `alignment_run_id` 等於目前發布的 run | 顯示 |
| 有記錄，但是別的 run | 不顯示 |
| 沒有記錄（欄位加入前排入的舊項目），在疊合影像上分析 | 只在面板上開啟該報告時顯示（與改動前相同） |
| 不是在疊合影像上分析 | 不顯示 |
| 單次執行 | 只在開啟時顯示（與改動前相同） |

沒被畫出來的報告數會在面板下方提示。

### 5.3 實作要點

- `useHeatmapLayers` 收一串 `HeatmapLayer`（每份報告一個），每份報告各有兩個圖層元素加一個標籤。
- overlay 的堆疊順序就是加入順序，所以報告清單一變就**整組重建**，確保新的在上面。
  標籤在所有熱圖之後才加入，不會被後面的熱圖蓋住。
- 每份報告各打一次 `/api/hybrid/heatmap`（`useQueries`），query key 是 `['heatmap', itemId]`，
  和單份顯示共用快取。

### 5.4 已知限制

- **後端重啟後要重新發布對齊結果**。「目前發布的是哪個 run」只存在記憶體裡，重啟後到重新
  發布之前，疊合檢視無法確認影像來源，不會畫任何有記錄的報告。
- **同一個 run id 重新上傳、重新對齊**：舊報告仍會被當成屬於它，沒有處理。
- **整張切片縮到最小時**，小區塊的異質性外框難以辨識（一格只剩幾個像素），要放大看，
  或靠角落標籤找位置。
