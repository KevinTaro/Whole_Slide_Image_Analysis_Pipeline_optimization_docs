**`mkdir` hoist out of `_save_tile_array` (doc 24 Candidate G)** — built, ablated at `workers=1` and `4` (n=2, interleaved), then **reverted**: the redundant syscalls are **0.056% of wall** (0.075 s of a 135 s run; ~0.8 s over a whole slide), the end-to-end ablation reads +0.63% / +0.80% — i.e. nothing outside the run-to-run spread — and the concurrency contention it was supposed to fix is real but bounded (2.6 µs/call at P=1–2, 5.1–5.3 µs at P=4–6, ~2 s per slide). The patch is preserved verbatim in §10 of that doc; **re-measure before reviving it if slide output ever moves to a network filesystem**, where a redundant `mkdir` is ~1000× more expensive (§3, §11).
**Background-tile placeholder writes (doc 24 Candidate F)** — measured for the first time (24 ms per background tile, 7.5% of wall, ~6 min at full-WSI scale) and **not built**: all of it sits on the BG arm, which finishes with **47–53% of its capacity unused** (BG/MAIN = 0.47–0.53 at real composition), so removing all of it moves wall by zero. The `os.link` alternative is 272–407× cheaper if it is ever wanted — but the real argument for it is **storage, not speed**: blank tiles write 10.2 MB each of uncompressed, entirely constant TIFF, ≈ **157 GB per slide** (§4).
**`detect_all_dots` / `enlarge_cell_instances` / per-tile debug encode → GPU (doc 24 Candidates B/D/E)** — closed on measurement rather than estimate: every one of them is BG-arm work, so at real composition their wall ceiling is **1.00×** until MAIN sheds ~50% first (§2.3/§2.4).
**Cross-tile Cellpose batching at G=16** — the one item doc 24 reopened, closed again: **+6.6% (M2) / +5.9% (M3b) slower** than G=1 and **15.8 GB** peak allocation, i.e. 48.6% of the card for one process (§7).

## 4. How to use this file

- **Picking up perf work**: start at §1, confirm the ceiling/status against
  [`measurement/bottleneck-list.md`](./measurement/bottleneck-list.md) (numbers here are a
  snapshot, that document's "All bottlenecks — status and result" table is the live source), then
  open the specific doc 10–25 for the item.
- **Need the full history of how a number was reached, or a candidate this file doesn't track
  in detail** (minor stop-losses, doc-only research leads, back-pocket ideas never sized): see
  [`../DISCOVERED-NOT-IMPLEMENTED.md`](../DISCOVERED-NOT-IMPLEMENTED.md) (the complete one-time
  audit) and [`measurement/bottleneck-list-history.md`](./measurement/bottleneck-list-history.md)
  / [`measurement/current-status-comparison-history.md`](./measurement/current-status-comparison-history.md)
  (the round-by-round measurement record). This file (19) stays the short, ranked, living list.
- **Picking up a documentation fix**: §3 lists what's known-stale; verify with `grep`/`find`
  against the current repo before editing (per this repo's own `codegraph-first` /
  `git ls-files`-over-trust discipline) — don't assume a doc's claim about another file without
  checking.
- **Closing an item**: update its status in the relevant table (or move it to "already closed"
  in §1) and link the record, the same way every other document in this folder cites its own
  evidence.
