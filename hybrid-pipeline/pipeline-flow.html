1主流程 M0→M1→M2→M3→M0→M4

M0 讀取→ M1 疊合→ M2 分割→ M3 細胞/點位→ M0 縫合→ M4 匯出

↳ cr 隨即出作用域 → 該塊所有 numpy 立即可 GC

每 tile 結束：torch.cuda.empty_cache() + gc.collect()（防長 batch 記憶體單調成長）
三層記憶體防線：模型（batch 級，載一次）→ 整圖畫布（tile 級，一張）→ chunk 中間產物（chunk 級，用完即 GC）。峰值恆定在「單塊處理 + 單張整圖畫布」。

3StitchAccumulator 核心區與去重（core-ownership）

相鄰 chunk 沿 overlap/2 切出互不重疊的「核心區」；一顆細胞只算在「其質心落在哪塊核心區」的那一塊 → 跨塊重複自動消除，不需 IoMin 的 O(n²) 兩兩比對。

兩塊都會各自偵測到重疊帶裡的橘核（重複偵測），但只有質心所在核心區的那一塊認領它 —— 去重從 O(n²) 降到 O(n) 的單一判斷（bisect_right(cuts, 質心)）。貼圖時每塊也只貼自己核心區範圍，互不重疊。

4記憶體生命週期（鋸齒循環）

每個 chunk：讀入 + M1/M2/M3 中間產物 → 峰值；acc.add 後 cr 出作用域 → GC 谷底。整圖畫布是常駐基線（隨 WSI 大小）。

常駐畫布（不隨 chunk 數成長） 單塊 transient（用完即釋放） 峰值＝讀入+處理 谷底＝GC

WSI 的真正天花板在「常駐畫布」而非 chunk transient。對 156k×134k 的 slide，StitchAccumulator 一次 allocate 6 張 full-size numpy（輸出端） —— 換讀取端 reader 省不了這塊，解法是 ROI-only / 停止整片縫合（見 04-optimization-roadmap L2）。
