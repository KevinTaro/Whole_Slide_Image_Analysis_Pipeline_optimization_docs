DISH 核配對與計數 — 以核為中心 (v3)

cell_mask/hybrid · m3_elastic_matching.py + m3_dot_detection.py

一句話原則：每顆 DISH 核屬於離它最近的那顆細胞；紅黑點只在那顆核裡計算，全部記給它的擁有者。

0. 你回報的兩個問題

你看到的根因屬於
#392 旁邊有橘色核卻沒配到，反而被遠處的 #388 搶走 配對用「細胞向外膨脹去壓核」，大細胞膨脹得遠 → 跨界搶核； 真正最近的小細胞膨脹搆不到，連候選都排不上 Part A
#296 已搶到核，#279 卻還算 2/2 計數用「細胞領地」切點，一顆核跨在 296 / 279 兩顆的領地上， 落在 279 那半邊的點就被記給 279 Part B

兩者其實是同一個原則的兩半：配對與計數都改成以核為中心。

Part A — 配對：每顆核配給「最近的細胞」

舊：細胞膨脹搶核

每顆細胞依面積向外等向膨脹 r ≈ 0.13·√面積，壓到哪顆核就收為候選。

不對稱：大細胞膨脹得遠、搆得到遠核；小細胞膨脹得近、搆不到。 於是夾在中間的核被較大的 388 搶走，最近的小 392 反而不是候選。

新：核找最近細胞

每顆核量自己中心到附近各細胞邊界的距離（核中心落在細胞內 = 0）， 在容忍值 max_dist_px 內最近者必勝。

對稱：不管細胞大小，核一定歸給離它最近的那顆。392 最近 → 拿到核；388 較遠 → 搶不走。

同一個場景，兩種結果

程式邏輯（m3_elastic_matching.py）

# 對每顆 DISH 核：
for did in dish_ids:
    cy, cx = 核 N 的 centroid
    win = strict_instance_mask[ 以 (cy,cx) 為心、半徑 tol 的小視窗 ]
    每個出現在視窗內的細胞 → 取「到核中心的最近 pixel 距離」= 邊界距離
    cand = { 細胞 : 邊界距離 }  其中 距離 <= tol          # 容忍值內才算候選
    had_feasible |= cand.keys()                          # 記錄「曾是某核候選」
    winner = min(cand, key=距離)                          # ★ 最近者必勝
    result[winner].append(did)

Part B — 計數：ROI = 配對到的核區域

舊：細胞領地計數

計數遮罩 = IHC strict 領地 ∪ 核補位。一顆核如果跨在 296 與 279 兩顆的 strict 領地上， 核落在 279 領地的那半邊仍算 279。

於是同一顆核裡的紅黑點被沿細胞邊界切兩半：一半 → 296，一半 → 279。 這就是 279 偷算到 2/2 的來源。

新：核區域計數

計數遮罩 = 把整顆配對核標成它的擁有者 id（nucleus_owner_mask），其餘為 0。

整顆核的點全記給贏家 296，不管核壓到誰的領地。沒配到核的細胞（279）在遮罩中沒有任何 pixel → 計 0 點。

四種結局（核數 → 怎麼算）

核數 1 · valid
正常細胞。在那顆核內計紅黑點、算 HER2/CEP17。
核數 ≥2 · 多核
被 ≥2 顆核選中 → 排除、打 X、不計入（multi_nucleus）。
核數 0 · drop-out
曾是某核候選（在 tol 內）卻競爭落敗、無備援核 → 排除、打 X（drop_out）。
核數 0 · 無候選
從頭就不在任何核的 tol 內 → 沒核可算 → 顯示 0/0、照常計入。

橘色 = 沒被任何細胞配到的核（孤兒） 粉色 = 已配對的核 紅 X = 被排除（多核 / drop-out）

參數

參數意義預設
dish_elastic_max_dist_px 核中心到細胞邊界的最大容忍距離（px）。≤ 此值才可能配給該細胞，最近者勝。 以核為中心配對的唯一距離閘值。50
dish_elastic_exclude_zero 是否把 drop-out（競爭落敗無備援）細胞打 X 排除。 不影響「無候選 0/0」細胞——那種一律計入。True
dot_blue_exclude_threshold 核數 ≥ 此值 → 多核排除。2
dish_elastic_expand_factor 已棄用：舊「細胞膨脹搶核」法的面積倍數，新版不再膨脹細胞，此參數無作用。—
