大 Patch Sliding-Window 分割 + 接縫縫合

把整圖一次跑的 pipeline 改成「1k 視窗逐塊分割 → 接縫縫合 → 整顆細胞下游分析」，並驗證邊緣細胞計算問題。

1問題

現實任務中，醫師手切的 WSI patch 是正方形、解析度 ≥ 1k（可能 2k / 4k / 8k…）。整張載入記憶體跑分割不可行，產線只能以 1k 視窗逐塊推論。但這樣會在視窗邊界把細胞 / DISH 核切成數塊：

  • 被切一半的細胞無法正確計數。
  • 紅 / 黑點（CEP17 / HER2）若被接縫砍成非圓形，會在後續偵測中漏掉。

核心觀察：這個「被切」問題只發生在兩個 Cellpose 分割步驟（M2 細胞、M3b DISH 核）。M1 UNet 早已內建 sliding-window 並回傳整圖 mask；點位偵測本就是逐細胞且 joblib 平行——只要細胞先被縫合成完整 instance，點就永遠不會被切。

2解法總覽

只把分割視窗化並縫合，下游（彈性匹配 / 點偵測 / 匯出 / per-cell crop）原封不動地跑在縫合好的全域 canvas 上。

M1 UNet 核心遮罩
(原本就 sliding-window) → M2 視窗化分割 + 接縫縫合 → M3b DISH 核 視窗化分割 + 縫合 → 彈性匹配 / 點偵測 / 匯出
(整顆細胞，無改動)

切窗 / 縫合策略採 鄰接視窗 + 並查集（DisjointSet）接縫合併——對應「用 set + 查看上下左右」的直覺：

  1. 逐視窗推論：1k 無重疊視窗各跑 Cellpose，每視窗 label 加累積偏移避免撞號，寫入全域 int32 canvas。
  2. 接縫聯集：對每條內部接縫（x = k·1024 / y = k·1024），檢查「上下左右」跨縫相鄰且雙方皆非零的 label pair，接觸像素數 ≥ 門檻就 DisjointSet.merge() 成同一顆。
  3. relabel：依聯集根把全域 canvas 重新編成 1..N 連續整數。
  4. 清邊只清外緣：縫合之後才 clear_border，因此只移除碰觸 patch 真實外緣的細胞，內部接縫細胞已縫合不受影響。
for each interior seam line (x=k·tile / y=k·tile):
    a = canvas[..seam-1];  b = canvas[..seam]
    pairs = unique( (a,b) where a>0 and b>0 ), with counts
    for (la, lb), n in pairs:
        if n >= min_seam_contact_px:  ds.merge(la, lb)   # 上下左右
relabel canvas by DisjointSet roots → 1..N
為何不用更簡單的「整圖丟 Cellpose 內部 tiling」？ 那雖幾乎零新增 code，但沒有真正接縫可驗證，也無法外推到真正無法整載的超大 patch。本方案在 4k 上跑出真實接縫，正好用來驗證邊緣細胞縫合是否正確（task2 的目的）。

4驗證結果

單元測試（無 GPU）

  • 跨接縫細胞 → 縫合成同一 id；內部細胞維持獨立 id。
  • 接觸門檻調高 → 不縫合（拆回 2 塊），門檻機制有效。
  • 單一 1k 影像 → 只跑一塊、無接縫，行為與直接 predict 相同（向後相容）。
  • <1k 與 IHC/DISH 尺寸不一致 → 正確拋 ValueError。

5如何執行

python hybrid_pipeline.py --ihc PATCH.tiff --dish PATCH.tiff

# 批次（test_picture 內的 4k 驗證圖）
python hybrid_pipeline.py --batch --test

輸出命名沿用原邏輯（{tile_id}_report.csv、{tile_id}_overlay.png、cells/cell_{id}.png …），差別是 *_overlay.png 多了 1k 視窗虛線格。

6已知限制與後續

  • 誤併風險：密集組織中兩顆不同細胞剛好貼著接縫，可能被誤併成一顆。DISH 核多為圓形且分離，風險低；若實測出現可調高 window_seam_min_contact_px（接觸像素門檻）。
  • 更穩的升級路徑：若鄰接縫合的切細胞 artifact 影響精度，可改成「重疊 halo 視窗 + IoU 去重」（細胞永不被切），程式較多但更穩。
  • 真正串流（未來）：目前下游仍在記憶體全域 canvas 上跑（4k/8k 足夠）。若要處理真正無法整載的超大 patch，需把 dish_mask_overlay 與點偵測也改成逐區塊串流——本次架構（分割視窗化 + 縫合）已是其墊腳石。
