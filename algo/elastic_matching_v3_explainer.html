DISH 核配對與計數 — 配對以細胞為中心 · 計數以核為中心 (v4)

backend/algorithms/hybrid · m3_module/m3_elastic_matching.py + m3_module/m3_dot_detection.py

一句話原則：每顆 IHC 細胞認領至多 1 顆 DISH 核（壓在身上的優先、其次最近的）； 紅黑點只在那顆核裡計算，整顆核全記給它的擁有者。
本頁的狀態：Part B（計數）自 v3 起未變，仍與程式一致。 Part A（配對）於 v4 重寫——v3 的「以核為中心、核找最近細胞」已被 「以細胞為中心 + 重疊優先 + reach」取代，連帶移除了「多核排除」這個結局。 參數表亦隨之更正。程式永遠是唯一權威： m3_module/m3_elastic_matching.py 的 module docstring 與 elastic_dish_nucleus_matching() 的 docstring 描述的就是現行流程； 本頁若與其牴觸，以程式為準。

Part A — 配對：每顆細胞認領至多 1 顆核（重疊優先 · 最近優先）

v3（已淘汰）：核找最近細胞

每顆核量自己中心到附近各細胞邊界的距離，容忍值內最近者必勝， 核可以同時被算給多顆細胞 → 需要「多核排除」這個結局來收尾。

問題：純距離閘值無視「核其實壓在某顆綠框上」這個更強的物理證據， 仍會出現「附近有橘核卻配不到」。

v4（現行）：細胞認領核，重疊優先

每顆細胞的候選有兩來源：(a) 像素重疊——與綠框有任一像素重疊的核； (b) reach 半徑——reach = max(√(factor·area/π), min_reach_px)， 質心落在半徑內的核。

一對一：先把重疊對依質心距離升冪配並 lock，再配僅 reach 對。 每顆細胞至多 1 核，落敗者自動往下找仍可用的核 → 不再有「多核」結局。

兩階段配對：壓在身上的先配

程式邏輯（m3_module/m3_elastic_matching.py）

# Step 1：兩張 label mask 各算質心；細胞另算面積以決定 reach
cell_centroids, cell_areas = _centroids_and_areas(strict_instance_mask, ihc_ids)
nuc_centroids, _           = _centroids_and_areas(dish_nucleus_mask, dish_ids)
reach = max(sqrt(factor * area_c / pi), min_reach_px)   # 每顆細胞一個

# Step 2：兩種候選來源
overlap = _overlap_pairs(strict_instance_mask, dish_nucleus_mask)  # 有像素重疊者
reach_pairs = { (c, d) : 核 d 質心落在細胞 c 的 reach 內 }

# Step 3：重疊對先配，再配僅 reach 對；兩批都依質心距離升冪、貪婪一對一
for (c, d, dist) in sorted(overlap_pairs, key=dist) + sorted(reach_only, key=dist):
    if c 未配 and d 未被 lock:
        result[c] = [d];  lock(d)                    # ★ 每顆細胞至多 1 核

drop_out = { 曾出現在任何候選對、最終仍 0 核的細胞 }   # 競爭落敗者

Part B — 計數：ROI = 配對到的核區域

舊：細胞領地計數

計數遮罩 = IHC strict 領地 ∪ 核補位。一顆核如果跨在 296 與 279 兩顆的 strict 領地上， 核落在 279 領地的那半邊仍算 279。

於是同一顆核裡的紅黑點被沿細胞邊界切兩半：一半 → 296，一半 → 279。 這就是 279 偷算到 2/2 的來源。

新：核區域計數

計數遮罩 = 把整顆配對核標成它的擁有者 id（nucleus_owner_mask），其餘為 0。

整顆核的點全記給贏家 296，不管核壓到誰的領地。沒配到核的細胞（279）在遮罩中沒有任何 pixel → 計 0 點。

同一顆核，兩種計數

程式邏輯（m3_dot_detection.py）

# 計數 ROI：每個 matched 核 pixel → 擁有者 IHC id，其餘為 0
count_mask = _build_nucleus_owner_mask(dish_nucleus_mask, dish_ids_by_cell)

for cid in 所有 IHC 細胞:                # 連沒核的也建結果 → 維持 0/0 計入
    per_cell[cid] = CellDotResult(cid)
for cid, 核bbox in 有核的細胞:
    ROI = (count_mask == cid)            # 只在「自己贏得的核」內偵測紅黑點
    偵測紅/黑點 → per_cell[cid]

三種結局（核數 → 怎麼算）

核數 1 · valid
正常細胞。在那顆核內計紅黑點、算 HER2/CEP17。
核數 0 · drop-out
曾是某核的候選（重疊或 reach 內）卻競爭落敗、已無可用核 → 排除、打 X（drop_out）。
核數 0 · 無候選
從頭就不與任何核重疊、也不在任何 reach 內 → 沒核可算 → 顯示 0/0、照常計入。

v3 的第四種結局「核數 ≥2 · 多核排除」已不存在：一對一配對下每顆細胞 至多認領 1 核，該情形在建構上不可能發生。

橘色 = 沒被任何細胞配到的核（孤兒） 粉色 = 已配對的核 紅 X = 被排除（drop-out）

參數

參數意義預設
dish_elastic_expand_factor 使用中（v3 的本頁誤標為「已棄用」）：細胞面積放大倍數， 用以算 reach 半徑 √(factor·area/π)。 候選來源 (b) 的距離閘值。1.5
dish_elastic_min_reach_px reach 的絕對下限（px）。用來橋接「核與綠框完全無重疊、但很近」的純飄移情形； 0 = 不設下限，只靠面積公式與重疊候選。20.0
cell_enlarge_area_factor 配對之前先把綠框實際往背景膨脹（skimage.expand_labels， Voronoi 式外擴、細胞間不重疊）使等效面積放大此倍數，藉此蓋到更多核。 與 reach 會疊加；1.0 = 不放大。只影響配對與點偵測， 醫師檢視的 overlay 仍畫原始 M2 綠框。1.5
dish_elastic_exclude_zero 是否把 drop-out（競爭落敗無備援）細胞打 X 排除。 不影響「無候選 0/0」細胞——那種一律計入。True
dish_nucleus_core_min_inside_ratio DISH 核需落在 UNet++ core_mask 內的最小像素比例。 1.0 = 完全包含才留；<1.0 容忍 mask 邊緣鋸齒。0.97

v3 的本頁列出的 dish_elastic_max_dist_px 與 dot_blue_exclude_threshold 在現行 config 中皆不存在—— 它們隨「以核為中心」配對法與「多核排除」結局一併移除。
